# 案例与证据

## 案例拆解

从验收矩阵的“操作与场景”和“通过条件”拆解，不只按标题生成一次点击。用 `RULE-01` 等稳定子编号，含 `ruleIds`、逐规则 `coverage`、`kind`、前置条件、步骤和可观察预期。新 run 的规则义务来自 `catalog.ruleAcceptance`；旧 E 流程只用于读取历史 run。

条件索引与可执行案例分开：按分号拆出的条件可用来查漏，但若步骤仍只是“执行原矩阵场景并核对本条件”，它还不是可执行计划，主 Agent 不确认 complete。案例需写清本轮具体测试对象、输入、动作与观察；如 T11 应明确 QQ/Gmail × 七类操作各自结果，不用一句“两家每项成功”代替逐项执行。共享前置和一次实际操作可以复用证据，但不能把原场景全集复制到每条条件中重复跑。

例如 B07 至少明确搜索、改名、归档隐藏、恢复、取消删除、确认永久删除，以及其他聊天/长期记忆保留。删除只对本轮创建的测试聊天执行。对 P02 应按每个页面/主题/空态/运行态对照，不能只以首屏一张截图通过。

主 Agent 对 `coverageReview` 中每个规则记录 `complete`、覆盖的 `scenarioIds` 和理由。缺一个规则场景、缺目录中已实现的局部案例，或仍有一个条件未验证，就保持未完整拆解。范围/约定用 `document`；界面 `ui`，视觉 `visual`，真实端到端 `integration`，逻辑自动化 `logic`。这只是证据分类，不改变原标准。

## 证据最低要求

| 结论 | 必须有的观测 |
| --- | --- |
| 界面/流程 | 当前构建、操作、对应 AX 状态或截图、实际结果；视觉差异另有同条件原版依据 |
| 持久化/隔离 | 创建的随机测试标记、重启前后结果及对应归属；不只看数据库里有一行 |
| 模型/工具调用 | 真实请求对应的结果、受控产物/服务回执及 thread/run 归属；不只用模型口头声称 |
| Voice/挂断/唤醒 | 实际媒体/设备条件、双向交谈和转写、停止后资源释放与再唤醒；无录音不得虚称有录音 |
| 电脑互斥 | 两个真实请求的排队/占用时间、可见操作与释放/接管状态；一次成功不证明互斥 |
| 邮件 | 测试地址、唯一主题、实际邮件 ID/回执和收件结果；草稿不等于发送完成 |
| 纯逻辑/约定 | 对应实际文件、测试输出或原始决定引用，明确没有证明的运行能力 |

截图导出使用工具实际公开的保存/导出能力；只有内联截图时记录工具会话/调用引用，明确“未落盘截图”，不要伪造图片路径。可以把实际 AX 观测与截图调用引用保存为证据文件，但文字索引不能替代需要像素对照的图像本身。不能导出又缺视觉证据时，视觉案例保持受阻。

证据文件在本次 `evidence`/`fixtures` 下，保留摘要和构建；不能只贴文件名而文件不存在。裁去/避开无关私人信息，认证密钥和完整媒体协议不要落盘。观察记录与模型推测分开。

## 夹具与外部条件

- Bot/群/聊天、目录、Webhook 和邮件都带 run ID 与随机标记，登记创建位置和归属。
- 文件任务限定 `fixtures` 及产品测试 profile 的工作区；归档恢复与永久删除用不同样本。任何清理都先核对路径真实归属，不能递归删除 run 根、项目根或日常目录。
- 默认复用认证只为模型执行，不修改日常 Codex 认证/全局设置。无另装 Codex 的 A02、独立认证的 A03、实际合盖的 V05 等条件未具备就记受阻，不擅自引入用户已排除的虚拟桌面或 VM。
- 测试收件人未给出、账号未授权、麦克风或 Computer Use 不可用时，列出最小前置条件；不把整组测试默默略去。

## 问题单与复验

问题单含 case/rule ID、严重程度、可复现前提、逐步操作、预期、实际、证据、应用/运行时版本。修复记录含修复 Agent 身份、修改文件、解释、构建和回归范围。主 Agent 的复验记录用新的实际操作与证据，注明问题是否关闭；同一问题的历史失败不能被覆盖或删除。
