# Agent 开发组织方案（额度优先，部分已确认）

日期：2026-10-20。状态：额度优先方案已用于实施。用户后续明确“开始吧”，P06 已更新为允许开始开发；部分角色安排仍可按任务调整。

## 1. 推荐组织方式

由主 Agent 持续担任总负责人。用户最新要求保留一个较强模型角色，主要消耗交给 Luna，见 [Q52](decision-followups.md#q52)。推荐主 Agent 使用 GPT-6.1 Sol，其余子 Agent 默认 GPT-6 Luna；不再采用前一版多个 Astra/Sol 子 Agent 的配置。主 Agent 的具体模型与思考强度仍为建议，尚未切换配置。

默认按需启用一个子 Agent；最多 3 个子 Agent、总并发 4 个仅为当前工具容量，不作为常驻配置。下表是职责划分，可由同一个 Luna 子 Agent 分批承担。按清晰的模块接口和文件所有权分工；主 Agent 负责跨模块取舍、集成和全量验收覆盖。独立复核使用释放的名额，并更换审查者。

| 角色 | 负责内容 | 交付物 |
| --- | --- | --- |
| 主 Agent／集成负责人 | 决策记录、模块接口、依赖顺序、任务拆分、公共文件、集成与进度 | 可追踪任务清单、集成结果、当前 117 条规则及其验收状态 |
| 界面与原版证据 Agent | REA 原版页面/组件/样式/资源/交互定位，建立对照，随后按基准实现界面 | 原版证据索引、共享 UI 规则、页面实现与对照记录 |
| Codex 运行时 Agent | 独立 App Server、认证、来源与会话、Voice、Computer Use 连接和生命周期 | 接入模块、协议适配、错误状态和真实能力证据 |
| 产品功能 Agent | 在接口明确后完成 Bot/群聊、记忆、计划、文件、连接器等任务包 | 指定模块实现、持久化迁移及对应验收材料 |
| 独立复核角色（轮换） | 检查实现是否符合决策、接口和代码规范，复核视觉和运行证据 | 分离的规格/代码审查结论、未完成项及修复要求 |

最后一行是轮换职责，不是额外并行 Agent。若某任务需要原生音频、邮件等专门调查，可在当前三个子 Agent 名额中调整任务，不长期无限增员。

## 2. 分工和集成规则

- 每个任务引用产品规则编号、原版证据和预期验收条件，不用“做得像 Grok”作为唯一任务描述。
- 先明确模块接口、输入输出、状态和错误，再并行处理实现。接口变化由主 Agent 集中协调。
- 一个写入范围同一时间只有一个负责人；公共类型、数据库迁移顺序、入口、依赖文件和公共样式由主 Agent 或明确指定的单一负责人处理。
- 开工后依任务使用独立分支/工作区；每批保持可集成，按依赖合并，不让多个 Agent 同时改相同入口文件。
- Agent 回报必须包含实际改动、对应规则、已取得证据、未验证项和集成注意事项；主 Agent 复读产物，不能只信“已完成”。
- 完成标准沿全量验收矩阵。阶段局部完成只记阶段进度，不能替代完整交付。

## 3. 开发顺序建议

1. **建立原版界面基准和接口契约**：界面 Agent 梳理真实页面与共用组件；运行时 Agent 核对独立包和协议；主 Agent 固定模块接口与任务依赖。
2. **先接通真实底层能力**：App Server、会话/认证与来源、Voice、Computer Use；处理已知阻塞。界面可沿既有原版基准并行实现，但模拟结果不能充当实际功能通过。
3. **按任务包接入完整产品功能**：记忆、计划、文件、群聊、邮件等根据接口和依赖排期，每包完成可独立复核的结果。
4. **持续做原版对照和独立审查**：统一组件先对齐，再扩展页面，发现偏差及时修正；额外功能继承原 UI。
5. **完成全量验收**：全部编号规则及跨功能流程逐项验证，补齐独立打包、真实设备、恢复和更新等证据。

这只是实施顺序，首版范围仍覆盖全部已确认功能。当前组织讨论不自动授权应用代码或运行验证；后续明确开工时再按已确认的授权范围执行。

## 4. 适用技能

| 技能 | 本项目用法 |
| --- | --- |
| grill-me | 一次确定一个尚未明确的开发组织/产品取舍，推荐后等用户答复 |
| reverse-engineer-anything（REA） | 取得 Grok 原版界面与交互证据，指导复刻和对照 |
| codebase-design | 将复杂实现收在清晰模块接口后，明确各 Agent 的协作接缝 |
| research / openai-docs | 核对接口、版本、官方源码与运行限制，形成项目内研究记录 |
| code-review | 在固定基点上分离检查代码规范与需求符合程度，由独立审查者复核 |
| tdd | 在获准编写/运行测试的阶段，把已定验收转为可执行测试并驱动实现 |
| diagnosing-bugs | 出现真实失败或性能问题时按证据定位和修复 |

prototype 可用于范围明确的技术实验；UI 的设计来源始终是 Grok 原版与复刻标准，不因技能提供风格生成能力而更换已定设计。当前只应用 grill-me 来确认组织方式，其余为后续使用建议。
