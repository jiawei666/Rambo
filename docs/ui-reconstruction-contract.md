# Grok Bot 界面复刻执行标准

日期：2026-10-20。状态：用户已明确 P02 的还原要求；本文件落实执行和验收方法，不表示页面已实现或视觉基准已收齐。

依据：[用户原话](decision-followups.md#p02-ui-fidelity)、[P02 产品规则](product-decisions.md)、[全量验收矩阵](acceptance-matrix.md)。

## 1. 必须遵守的还原方式

1. 已有功能的界面按 Grok Bot 原设计完全复刻，以 REA 反编译/静态分析定位到的原版结构、组件、样式、资源和交互为基础实现。
2. Grok Bot 没有而 Rambo 已确认需要的功能，使用同一套布局、字体、颜色、间距、控件、弹窗和状态规则扩展。
3. Rambo 名称、用户指定的新头像／Logo、Codex 接入和其他已确认产品差异照既定记录执行。
4. 功能范围仍以产品决策为准；UI 还原要求不自动恢复已排除的云电脑、团队空间、消息编辑/重生成等功能。

2026-10-21 [Q57](decision-followups.md#q57) 补充：群聊与单聊共用列表及界面样式，不单独设计“群聊”分组样式。群头像由多个成员机器人的头像组合呈现；拼合数量、重叠/网格布局等细节尚待实现对照，不在本条虚构固定数值。群内各条 Bot 回复仍展示实际发言者身份。此条是用户明确的 UI 要求，P02 的对照按此执行。

## 2. 先取得证据，再落实页面

- 固定参考安装版本、包摘要、窗口尺寸和系统缩放，避免把不同版本混成一个目标。
- 定位每个页面的路由/入口、渲染组件、共用样式、图标与资源，以及点击后的状态转换。
- 用源文件路径、偏移/行号、资源摘要及 REA Evidence 建立组件对照；minified 变量名本身不作为稳定身份。
- 对关键页面取得实际视觉基准。静态代码无法证明的展示状态标待核对，不能用自制示意图冒充原版截图。
- 新功能优先复用已经提取确认的原版组件组合；确需新增组件时，明确它继承了哪些原版规则。

## 3. 每个页面需对照的项目

| 项目 | 对照内容 |
| --- | --- |
| 页面骨架 | 侧栏、顶部栏、内容区、输入区、详情面板、滚动与固定区域 |
| 排版与尺寸 | 字体、字号、字重、行高、控件高度、图标尺寸、内外间距、对齐与截断 |
| 视觉属性 | 背景、前景、边框、圆角、阴影、分隔线、选中/悬停/聚焦样式 |
| 组件内容 | 标签、按钮位置、菜单层级、提示文案、空状态、文件卡片与操作入口 |
| 交互 | 点击、键盘、切换、展开/收起、弹窗打开/关闭、焦点与滚动行为 |
| 执行状态 | 待机、输入、运行、等待、完成、失败、中断、不可用及重连等对应呈现 |
| 动态细节 | 动画、过渡、加载反馈、内容增长与窗口变化时的布局行为 |

没有从原版核实的具体色值、尺寸和动画时长保持待提取，不先发明一套数值写成“原版”。

## 5. 完成判据

每个区域交付一份“原版来源 → Rambo 组件 → 实际页面截图/交互结果 → 差异处理”的记录。已有功能逐项对齐原设计；额外功能逐项证明与原组件体系一致。名称、Logo 及已确认功能差异明确列出。

缺原版证据或未完成对照的页面保持待验收；全部已确认页面和功能完成后才按 P08 报完整交付。本文不新增消息编辑/重生成、语音切 Bot 或其他用户已拒绝的能力。用户后续已授权开始开发，实施状态沿 P06 和 implementation-progress.md；首批静态依据见 ui-baseline.md。
